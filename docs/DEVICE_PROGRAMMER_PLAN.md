# 设备烧录与 RTT 设计计划

状态：2026-10-01 确认的实施方向。参考 HSLinkNexus 的经验，但不复用其针对 STM32G431 的目标选择和地址推断。

## 目标与范围

- 第一批探针：ST-Link、CMSIS-DAP。暂不接入 J-Link，避免其驱动安装与分发问题。
- 支持导入用户提供的 CMSIS-Pack，并按供应商、Pack 版本、器件变体管理目标。没有可用烧录算法的目标允许入库，但必须标记为“不可烧录”。
- 提供固件烧录、擦除、读回与校验，以及可确认的下载选项。配置区/Option Bytes 作为独立的厂商能力提供，不能将任意寄存器写入包装成通用配置功能。
- RTT 提供双向字节流和频道选择。终端模拟器通过同一流接口连接 MCU 固件内的 Shell；RTT Viewer 和 Shell 模式只是不同的前端呈现与输入策略。

“任何单片机”应解释为：凡能通过受支持探针、核心架构、内存映射及可执行 Flash 算法描述的目标，可通过导入数据扩展，无须为每款 MCU 修改应用代码。仅有器件名称或内存表并不足以烧录；缺失算法、RAM 工作区或调试协议支持时要给出具体原因。

## 数据与责任边界

```
CMSIS-Pack (.pack/.pdsc) ─→ 导入与校验 ─→ 目标目录（持久化）
                                         │
探针枚举 ─→ 探针会话 ─→ 目标解析 ─→ FlashPlan ─→ 烧录执行器
                    │          │
                    │          └→ 厂商配置 Provider（可选）
                    └→ RTT 字节流 ─→ Viewer / 终端模拟器
```

1. **Pack 来源记录**：保存原始文件、SHA-256、供应商、名称、版本、导入时间及解析器版本。每次导入先写临时位置，解析和校验成功后原子提交；失败不得污染已有目录。相同 Pack ID 与版本、不同哈希视为冲突，要求显式替换。原始包不直接当作可信可执行代码。
2. **目标记录**：稳定键为 `vendor/pack/version/device`，并保存器件别名、核心、地址空间、RAM、Flash 区域、算法引用和能力诊断。多个 Pack 版本可并存。UI 默认展示较新版本，但工程配置锁定精确键与哈希，不因更新静默换目标。
3. **烧录算法**：PDSC 的 Flash algorithm/FLM 需要经受支持的转换器和 probe-rs 目标描述验证。转换产物带来源与哈希，绝不把未知 FLM 路径当成已可烧录。启动会话时构造独立的目标注册表，避免全局注册表更新影响已有会话。
4. **工程配置**：保存目标键、探针类型/序列号（可选）、连接方式、速度、复位策略、固件文件、BIN 基地址、擦除模式、校验与下载后动作。BIN 必须显式指定地址；ELF/HEX 使用文件地址并检查落入可写区域。不得以“最低 Flash 地址”推断 BIN 起点。
5. **FlashPlan**：在打开探针之前形成可预览计划，逐段列出目标地址、字节数、覆盖/擦除范围、算法、校验方式和风险。执行前再次核对所选 Pack 与文件哈希、区域边界及算法。用户选择目标并连接探针后可烧录；不同 MCU 的 ID 与容量寄存器不统一，通用烧录流程不读取这些寄存器作为门槛。
6. **配置 Provider**：通用目录只描述能力和内存；Option Bytes、保护位等由芯片系列 Provider 实现读、解码、修改预览、写入、复读校验及复位影响。第一版先做只读能力探测，再按系列扩展写入；未知字段保持只读。
7. **RTT 会话**：与烧录/调试共享对探针的排他控制。后端把频道数据作为有序字节块推送，并接受带流控的写入；前端终端层处理 UTF-8 增量解码、ANSI、换行及 Shell 输入。连接中断要保留可见日志并明确重连状态。

## 实施顺序与验收

| 阶段 | 交付 | 验收条件 |
| --- | --- | --- |
| 1. 目标目录 | Pack 元数据导入、版本/来源管理、目标检索和能力诊断；持久化数据模型 | 同一器件不同 Pack 版本可辨；缺算法目标不会显示为可烧录；重启后来源可追溯 |
| 2. 探针与目标会话 | 枚举 ST-Link/CMSIS-DAP，选择目标、连接、识别与断开 | 不依赖固定 G431；错误目标或探针占用给出清楚错误 |
| 3. FlashPlan 与执行 | ELF/HEX/BIN 地址解析、范围检查、擦除、下载、校验和进度/取消 | 至少两种不同系列 MCU 实机烧录、读回一致；BIN 无地址被阻止 |
| 4. 高级配置 | 内存读写、系列配置 Provider、修改预览、写后校验 | 支持系列的字段能往返校验；未知系列保持只读 |
| 5. RTT 与 Shell | 双向频道、日志、终端模拟器适配 | MCU 内 Shell 可交互，断线与重连行为可见 |

每阶段都在界面显示“已验证/仅有描述/缺少算法/探针或核心不支持”状态。前两阶段不承诺所有 Pack 都能转换成功；兼容矩阵由导入诊断和实机验证逐步建立。

- Nationstech N32H47x_DFP 1.2.0：用户已导入，目录识别 28 个器件、两份 FLM；加入转换与目标定义校验样本。
- STM32F407ZGT6：首个实机烧录验收目标。本机有 Keil STM32F4xx_DFP 2.14.0，可导入 `STM32F407ZGTx` 定义；用户已提供 Zephyr 固件目录，实机验收由用户手动执行。

## 实施进度

- 已完成目标目录、Pack 导入与来源保存。
- 已接入 `target-gen 0.32.0` 将 FLM 转换为 probe-rs 目标定义，并逐器件保存校验结果；该校验不执行实机烧录。离线样本验证结果：N32H47x 28/28、STM32F1 95/95、STM32G4 183/183 个目标定义有效。
- 已加入 ST-Link/CMSIS-DAP 专用探针枚举和一次性 SWD 连接测试。连接测试按选择的目标附着后立即断开，不执行 Flash 写入，但调试附着可能影响正在运行的固件；它不能证明实际芯片型号。
- 已加入持久探针会话：附着后保持连接直到显式断开，会话排他占用探针；支持暂停 / 继续主核心以及一次性 RAM 读取（读取前自动暂停，读取后保持暂停，由用户决定何时继续）。会话级错误事件推送与断线检测待补充。
- 已加入 BIN/ELF/HEX 烧录计划预览：BIN 必须填写起始地址；ELF 读取可加载段的物理加载地址，HEX 读取记录地址。逐段检查非别名 Flash 区域和烧录算法，拒绝重叠或越界段。PDSC 中 Flash 的 `rx` 是 CPU 访问权限，不等同于算法不可烧录。计划包含文件哈希、逐段写入范围与扇区擦除范围；执行前重新核对。
- 页面拆为“Pack 管理”和“固件烧录”：前者负责导入、目标定义校验与器件目录；后者是左侧目标、固件、烧录计划和右侧探针连接、目标信息的工作台。选好目标即可连接探针，无需先预览固件或读取芯片 ID。BIN 地址默认 `0x08000000`，可手动改；选固件或修改地址后自动更新计划。高级诊断保留在折叠区。
- BIN/ELF/HEX 写入流程已接入：执行前重新检查目标定义、Pack、固件哈希和逐段范围；点击“烧录并校验”即执行，无需芯片 ID/容量 Provider。使用 probe-rs 扇区擦除、写入后读回校验；受影响扇区内未被固件覆盖的旧数据也会被擦除，不保留写入段范围外字节。已离线验证 F4 与 N32H47x 的 Pack 目标定义及固件解析；实机烧录仍由用户验收。进度事件、取消、配置区和 RTT 仍待实现。
- 已提供独立的“全片擦除”操作：按所选 Pack 寻找唯一主 Flash 区域和覆盖该区域的算法，预检扇区表后擦除并读回检查是否为 `0xFF`；不读取厂商专属 ID 或容量寄存器。Pack 无法唯一确定主区域或算法时拒绝擦除，避免波及其他非易失区。操作前保留全片擦除确认。配置选项入口按 MCU 专属读写定义开放，当前无可安全修改的 Provider，因此按钮禁用，不能把 Pack 烧录算法当成配置位定义。

## STM32F407ZGT6 手动验收步骤

1. 在“Pack 管理”页导入 STM32F4xx_DFP Pack，等待目标定义自动校验；再到“固件烧录”页选择 `STM32F407ZGTx`（或该 Pack 中对应的 `STM32F407ZG`）。
2. 在右侧选择 ST-Link 或 CMSIS-DAP、对应探针及 SWD 速度并连接；连接后自动读取设备 ID 与 Flash 容量。
3. 选择为该板编译的 `zephyr.bin`；已核对 `wujique-f407zg / stm32f407xx` 构建配置与 ELF 的 Flash 起始地址 `0x08000000`。明确填写 BIN 起始地址 `0x08000000`。
4. 预览固件哈希、写入地址和将受影响的扇区范围。当前 66,912 字节样本跨过 64 KiB 边界，不能只擦除第一个扇区。烧录按钮由探针连接和有效计划启用，目标选择由操作者负责。
5. 点击“烧录并校验”，等待读回校验成功后再断开或继续运行。若失败，视 Flash 为可能已部分改变，先检查错误和供电，不直接假定原固件仍完整。

实机操作由板卡持有人执行；首次验收结果与探针型号仍待记录。当前样本 `zephyr.bin` 的 SHA-256 为 `4B1611C727E093566F6710DFCCE5667DF269E1C7E9204759D163448698845B8A`。
- 后续按探针连接与目标核对、烧录执行器、配置 Provider、RTT/Shell 的顺序推进。实机验收还需要具体板卡、探针和固件样本。
